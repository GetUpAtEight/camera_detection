# 低频巡检 · 稀疏采样篡改检测

> 面向「**成本受限、不能实时拉流**」的场景：每 1 小时（甚至 1 天）才拉一次帧，
> 每次可以只拉 1 张，也可以连拉 3~5 帧组成一个几秒长的"微序列"。
>
> 与 `docs/ALGORITHMS.md` 那套实时逐帧算法是**两套独立链路**，不要混用。

---

## 1. 为什么不能直接复用实时算法

实时链路（`/detect/image`、`/live/sessions`）的 9 个算法里，有 6 个依赖"帧间连续性"：

| 算法 | 依赖 | 1 小时一次时会怎样 |
|---|---|---|
| `scene_diff` / `orb` / `edge` | 参考帧 | 有参考帧就能算，但参考帧从"上一帧"变成"上一次抽样"，语义全变 |
| `frame_area` | **上一帧** | 永远拿"一小时前"当上一帧 |
| `mog2_area` | 内部背景模型 + warmup≥5 | 每次抽样都是"预热第 1 帧"，永远不告警 |
| `shortlong` | 短/长池 ≥15 帧 | 攒不够，永远返回"长池积累中" |

更根本的问题在**状态生命周期**：实时链路的帧间状态存在算法层内存里，
且 `server.py` 的 `_SESSION_TTL_S = 30 分钟` 就回收。两次抽样间隔 1 小时，
内存态必然已经过期 —— 于是每次抽样都从"第 1 帧"重新开始，基线永远建不起来。

所以本功能把 **机位态**（跨抽样、可存几周）与 **会话态**（单次抽样内、秒级）**彻底分开**：
机位态按 `cameraId` 落盘到 `algo/data/sparse/`，不随会话回收。

---

## 2. 三层信号模型

整个判定的骨架是"三层"，每层能回答的问题不同：

| 层 | 时间尺度 | 能判什么 | 实现 |
|---|---|---|---|
| **L0 长周期** | 相邻采样点间隔 1h~1d | 与历史基线的偏离、持续篡改、已发生的移位 | `sparse/metrics.py::robust_z_profile` / `phase_shift` |
| **L1 微时序** | 单次抽样内部 K 帧（2~8 秒） | 冻结/重放、正在被转动、样本质量门控 | `sparse/metrics.py::analyze_burst` |
| **L2 单帧** | 任意单帧 | 失焦、遮挡、画质退化 | `sparse/metrics.py` 的 L2 指标簇 |

### 2.1 L0：按槽中位数背景 + 逐像素鲁棒 z

```
slot   = (ts // 3600000) % 24          # 按小时分 24 个时段槽
median = median(该槽历史样本缩略图)      # 同时段的中位数背景
mad    = median(|样本 - median|)        # 逐像素 MAD（有下限，见下）
z      = |current - median| / (1.4826·mad)
dHist  = mean(clip(z, 0, 5)) / 5
离群占比 = mean(z > 3)
```

三个设计要点：

1. **按小时分槽**：1 小时一次采样时，同槽样本天然落在"每天同一小时"，
   自动吸收昼夜光照变化 —— 这正是 `docs/ALGORITHMS.md §10.1` 记录
   "绝对阈值在真实素材上同时太灵敏与没反应"的根因。
2. **用 MAD 而不是标准差**：篡改往往只占画面一小块，标准差会被正常区域稀释。
3. **MAD 必须有下限**（`MAD_FLOOR = 2.0` 灰度级）：压缩视频的静止画面可能让
   基线样本"过度稳定"，MAD 趋近 0 时 z 会被放大到几十，正常噪声也会判成篡改。

### 2.2 L1：9 个微时序指标 + 运动×噪声象限

`analyze_burst()` 输出 9 个指标：

| 指标 | 含义 |
|---|---|
| `bitExactDup` | burst 内逐位完全相同的帧对占比 |
| `intraMad` | 相邻帧平均绝对差（**去噪后**） |
| `intraChangeRatio` | 去噪后差异 >8 灰度级的像素占比（结构性变化） |
| `intraEdgeRate` | 边缘图变化率 |
| `intraOrbTranslation` | burst 内 ORB 平移量（px） |
| `intraSharpnessVar` | 清晰度变异系数 |
| `sigmaPerFrame` | **帧间时间噪声** σ（冻结时趋 0） |
| `lumaDrift` / `chromaDrift` | 亮度/色度漂移（样本可用性） |

两个容易踩的坑，实现里都处理了：

1. **运动必须用去噪后的帧差**。传感器噪声本身 σ≈3 灰度级，直接帧差算出的
   `intraMad≈0.013`，会被误判成"画面在动"，于是任何静态场景都进不了 Q2。
2. **噪声必须用帧间时间残差，不能用空间残差**。空间残差里混着场景纹理；
   而"同帧重复"与"真实摄像头"的本质区别在时间维度：真实传感器每帧独立噪声
   ⇒ 相邻帧差有非零方差；冻结重放 ⇒ 帧差恒等于 0。

运动 × 噪声构成 4 个象限：

| 象限 | 条件 | 含义 |
|---|---|---|
| Q1 | 有结构变化 + 有噪声 | 正常活动场景 |
| Q2 | 静止 + 有噪声 | **合规静态场景（不判）** |
| Q3 | 静止 + 无噪声 | **冻结/重放** |
| Q4 | 有动态 + 无噪声 | 可疑合成 |

### 2.3 冻结/重放的 4 条判据

| 判据 | 强度 | 说明 |
|---|---|---|
| **D1 跨采样点 bit-exact** | 极强 | 当前帧与**历史某次抽样**逐位相同。独立采样不可能产生完全相同的像素 |
| D2 burst 内 bit-exact | 弱 | 只作辅助。H.264 静止场景的 skip macroblock、3DNR 都会让连续帧高度相似 |
| D3 噪声缺失 | 强 | burst 内帧间时间噪声 σ 低于下限 |
| D4 σ 离散度下限 | 中 | 帧间噪声离散度 < 0.2% ⇒ 非独立采样 |

> **关键**：主判据必须落在**跨采样点**（D1），不能只看 burst 内部。
> 否则夜间空走廊（H.264 静止画面）会被打成误报灾难。
> 附带好处：这样冻结检测在 **K=1 模式仍然可用**，burst 只是加速器。

**首次抽样不定罪**：压缩流静止画面首次抽样也会"无噪声"，
所以 Q3 只在机位已有历史样本时才定罪；首次只记录哈希，等下一次用 D1 确认。

## 3. 判定流程（P-1 ~ P6）

```
                 ┌─ P-1 样本不可用（曝光/白平衡在 burst 内不稳）→ 不下结论、不入基线
                 │
  一次抽样 K 帧 ─┼─ P0  冻结/重放（D1 或 Q3）────────────────────→ 告警
                 │
                 ├─ P5  正在被转动（burst 内一致平移 + 高 inlier）→ 告警
                 │
                 └─ 稳定性分解 4 格矩阵
                       ├─ 高偏离 + 低动态 → P1/P2/P3/P4 持续篡改 → 告警
                       ├─ 高偏离 + 高动态 → 瞬时事件（有人经过）→ 不告警
                       └─ 低偏离           → 正常
```

判决常量见 `sparse/engine.py::SAMPLE_VERDICTS`：

| verdict | 中文 | 告警 |
|---|---|---|
| `normal` | 正常 | 否 |
| `freeze_replay` | 冻结 / 重放 | 是 |
| `persistent_covered` | 持续遮挡 | 是 |
| `persistent_defocused` | 持续失焦 | 是 |
| `persistent_moved` | 摄像头被移位/转动 | 是 |
| `persistent_change` | 画面持续异常（类型未定） | 是 |
| `object_change` | 场景内物体变动（不告警） | 否（可配） |
| `being_rotated` | 正在转动（采样瞬间捕获） | 是 |
| `transient_event` | 瞬时事件（不告警） | 否 |
| `information_insufficient` | 样本不可用（不下结论） | 否 |
| `cold_start` | 基线建立中（低置信） | 否 |

### 3.1 遮挡 vs 失焦的消歧

全遮挡画面的清晰度也会归零，所以"清晰度下降"**不能**用来判遮挡。真正的分界是**三个量**：

| 判据 | 遮挡（纸/手/布盖住） | 失焦 |
|---|---|---|
| 全局熵 | 显著下降 | 只降一点 |
| **全局对比度（灰度标准差）** | **崩塌**（画面趋于单一颜色） | **基本保留**（低频结构还在） |
| 低熵块占比 | 高 | 中 |
| **与基线参考帧的 NCC** | 低 | **高（≥0.5）** |

两条补充规则：

* 判失焦要求 **NCC ≥ 0.5** —— 如果画面内容根本换了，它的清晰度本来就可能更低，
  不能拿"清晰度下降"解释成失焦；
* 对比度判据（`relContrastDrop = 0.55`）是实测补上的：纸面有噪声和 JPEG 纹理时
  熵只掉 20% 左右，但对比度会掉到 90% 以上，是最强的遮挡信号。

### 3.2 移位 / 转动（已发生）的判定

**先明确一个物理事实**：1 小时采样下，摄像机被转动几乎**不可能**恰好发生在连拉那 3 帧的几秒内
（概率与瞬时事件同级，0.28%~0.42%）。所以真正要判的不是"正在转"，而是
**"上一次抽样到现在，视野变了"** —— 转动发生在两次抽样之间，下一次抽样必须能发现。

判定用三条互补的证据：

| 证据 | 手段 | 擅长 | 局限 |
|---|---|---|---|
| **参照物相似变换** | 多个标定参照物的对应点拟合 | 平移（含小角度） | 模板不具备旋转不变性，转大了会失配 |
| **全局配准** | 当前帧 vs 基线参考帧的 ORB 相似变换 | 平移 + **旋转** + 缩放 | 需要画面有足够特征点 |
| 相位相关 | 仅平移 | 无特征点的场景 | 噪声大，估不了旋转 |

三者是互补的：**平移主要靠参照物，旋转主要靠全局配准**。实测 12° 转动时参照物全部失配
（模板对不上），但全局配准给出 12.0° / 内点率 0.94，判决正确落到"摄像头被移位/转动"。

关键改进（针对"转了之后参照物移出小窗"这一漏检）：

1. **多尺度全幅搜索**：先在 1/4 分辨率上**搜全图**，再全分辨率精修。
   转动 15° 时建筑会大幅移出原位置，只在小窗里搜必然失配。
2. **相似变换拟合**：绕光心旋转时，画面不同位置的参照物朝**不同方向**移动，
   "位移一致"这个模型对旋转不成立。改为拟合「平移 + 旋转 + 缩放」，
   只要各参照物能被**同一个刚体变换**解释，就是机位真的动了。
3. **参照系失效 ≠ 没移位**：可信参照物不足时返回 `lost`，此时按下面的优先级判断——
   遮挡证据 → 按遮挡；全局配准出大旋转/大平移 → 判移位；
   与参考帧整体相关性「NCC < 0.45」（失焦时会 >0.8）→ 判"视野已换"；
   否则才考虑失焦。

### 3.3 参照物标定：抑制移位误报（推荐）

**问题**：全图相位相关在真实监控画面里过敏严重。树影、旗帜、水面、行人车辆、雨雪
都会把相关峰推偏；再加上缩略图只有 160×90，2px 的阈值≈画幅宽的 1.25%，一次轻微的
自动云台抖动就会触发。实测中「摄像头移动」是误报最多的一类。

**解法**：让用户标定几块**不会自己移动**的人造结构（大门、楼角、围墙、灯杆基座），
移位判定改为「这些参照物是否符合同一个刚体变换」。

```
标定阶段：
  用户在画面上框选 2~4 个矩形（归一化坐标 x,y,w,h ∈ [0,1]）
  → 从标定画面截取模板，存**梯度幅值图**（不是原始灰度）

每次抽样：
  对每个参照物：1/4 分辨率全幅粗搜 → 全分辨率精修 → (dx, dy, score, margin)
  可信判定：score ≥ 0.45 且 margin ≥ 0.05（峰值唯一，防重复纹理假匹配）
  用可信参照物的对应点拟合相似变换 → 平移 / 旋转 / 残差
  位移 ≥6px 或 旋转 ≥0.8°，且拟合残差 ≤3px  ⇒ 摄像头被移位/转动
```

**为什么用梯度幅值做模板**：对昼夜光照变化、镜头积灰、轻微失焦都不敏感，
而对"整体平移/旋转"极其敏感 —— 正好是我们需要的性质。

**为什么要"峰值唯一性"**：全幅搜索会带来假匹配。栏杆、地砖、窗格这类重复纹理，
或者干脆换了个场景，模板在别处也能凑出很高的相似度。真参照物应该是一个**尖峰**，
假匹配往往有一堆差不多高的次峰（`margin` 小）。

**为什么必须"同一个刚体变换"**：建筑物不会自己走。如果 3 个参照物都能被同一个
旋转+平移解释，那是镜头被转了；如果只有 1 个动了、其余不配合，那是那个位置上的东西变了
（门被打开、贴了告示、有人在墙上涂鸦），**不是机位变了**。

**标定后的行为变化**：

| | 未标定 | 已标定 |
|---|---|---|
| 主要判据 | 全图相位相关（过敏） | 参照物相似变换 |
| 大幅度转动 | 相位相关估不出旋转，常漏检 | 全幅搜索 + 相似变换，能判 |
| 参照物全部失配 | — | 走"参照系失效"分支，仍可能判移位 |
| 边缘结构变化 | 作为移位的次证据 | 不再使用（避免二次过敏） |


**标定建议**：

* 选 2~4 个，**分散在不同位置**（左、右、中），不要都挤在一角；
* 选边缘/角点丰富的结构，不要选大片纯色墙面（模板没特征，匹配不稳）；
* 不要选树叶、旗帜、水面、广告布（会被风吹动）；
* 不要选车辆、行人、可移动物体；
* 换机位/大改构图后要重新标定；只换光照不用重标（"重设基准"会保留参照物）。

### 3.4 忽略区与「场景内物体变动」

**问题**：真实监控里，桌上的杯子、椅子上的包、门口的纸箱每天都在被挪动。
这些变化会让**全图基线偏离**超阈值，于是天天误报"画面持续异常"。
而参照物管不了这件事——它只回答"机位有没有动"，从来不是"监控区域"。

两条互补的手段：

#### 忽略区（用户圈定，精确控制）

在标定界面把模式切到「忽略区」，圈出**会被频繁挪动、但不需要关心**的区域（桌面、货架、堆放点）。
这些像素**完全不参与** `dHist` 与离群占比的计算：

```python
ignore = region_mask(thumb_gray.shape, state.ignore_regions())
l0 = robust_z_profile(thumb_gray, median_bg, mad_bg, ignore=ignore)
# z_eval = z[~ignore]  → dHist / outlierRatio 都只在未忽略像素上统计
```

结果里会给出 `changed.ignoredRatio`（忽略区占画面比例）与 `analyzedRatio`（实际参与统计的比例），
避免"忽略太多导致什么都没在看"而不自知。

#### 局部变化降级（自动，可关）

即使没画忽略区，系统也会先看**变化的空间形态**：

| 变化形态 | 典型原因 | 处理 |
|---|---|---|
| 局部团块（最大连通块 ≤25%） | 桌上多了个箱子 / 少了把椅子 | `object_change`，记录但不告警 |
| 大面积 / 全局 | 遮挡、失焦、机位移动 | 正常判定与告警 |

判据：

```python
largest = 最大变化连通块占画面比例
if largest <= objectChangeRatio(0.25)
   and 不遮挡 and 不失焦 and 参照物未移动:
       → object_change（level=info，alarm=False）
```

**这是一个有意的取舍**：局部变化确实也可能是攻击（比如在镜头一角贴个东西），
但 1 小时采样下"每天都变的桌面"造成的误报远比这种风险更伤。
默认只记录不告警；要严格的话把 `objectChangeAlarm` 设为 `true`。

### 3.5 子块投票：抗参照物部分遮挡

**问题**：一辆车停在参照物（大门）中间，整块模板匹配的分数会掉到阈值以下，
被判成"参照物丢失"，进而可能误判成机位移动。

**做法**：整块匹配失败时，把参照物切成 **3×3 子块**，以整块给出的粗略位置为锚点，
每块独立匹配（±10px 内精修）：

```
9 块中 ≥4 块匹配成功（分数 ≥0.50）
且各块偏移一致（最大偏差 ≤3px）
⇒ 认定参照物仍在原处，返回 blockRatio（对上几块）与 partial（是否部分遮挡）
```

实测：中间一列被有纹理的遮挡物盖住时，仍有 **7/9 块**匹配成功、偏移一致。

**配套防呆（很重要）**：`TM_CCOEFF_NORMED` 在**搜索窗口近乎纯色**时会返回虚高的分数
（分母趋 0）。所以匹配后必须检查"匹配位置是否真的有梯度能量"——
`energyRatio = mean(匹配区域梯度) / mean(模板梯度) < 0.30` 一律判定为不可信。
没有这条，"镜头被完全挡死"会被判成"匹配得非常好"。

### 3.6 光度对齐：天气/昼夜变化不误报

**问题**：阴天、黄昏、开灯会让整幅画面整体变暗或对比度下降。这是**全局仿射变化**，
不是篡改，但它让每个像素都偏离基线，`dHist` / 离群占比一起升高。

**做法**：做逐像素比对**之前**，先拟合 `cur ≈ gain × base + offset`，
把当前帧反变换回基线的光度尺度：

```
残差比 residualRatio = std(残差) / std(当前)
只有 residualRatio ≤ 0.25 才采用对齐结果
```

为什么要有这个门限：如果画面里**真多出来东西**，拟合会被那些结构带偏，
反而把没变的区域也系统性偏移 —— 那是帮倒忙。实测：

| 场景 | gain | residualRatio | 结果 |
|---|---|---|---|
| 阴天（对比度 65%、压暗 85%） | 0.65 | 0.025 | dHist 0.08 → **正常** |
| 车停进来 | ≈1 | 0.4+ | 不对齐，照常检出 |

注意：对比度仍在**原始帧**上计算（见 §3.1），否则遮挡造成的对比度塌陷会被一起"归一化"掉。

### 3.7 参照物模板库（多外观模板 + 人工反馈）

**问题**：下雨、下雪、季节变化、光照方向改变会改变参照物的**外观结构**（比如树影消失、
门上有积雪）。这时模板匹配分数会掉到阈值以下，参照物被判"丢失"。

**做法**：一个参照物不再只有一个模板，而是**模板库**：

```
参照物 1
 ├─ t0  主模板（标定时自动生成，不可删除）
 ├─ t1  「夜间版」（客户补录）
 ├─ t2  「雨天版」（客户补录）
 └─ …   上限 8 套/参照物，超出按最旧淘汰
```

匹配时**逐个模板试，取最高分**；某个模板分数 ≥0.85 就早停，避免模板数线性放大算力。
返回里会带 `templateId`，能看出来是**哪一套**模板命中的。

**三个补录入口**：

| 入口 | 场景 | source |
|---|---|---|
| 标定界面「用当前画面补录」 | 例行补录（夜间/雨天） | `manual` |
| 判定结果页「这不是篡改 · 加为参照物模板」 | **误报反馈**：客户确认这是正常画面 | `false_alarm` |
| 导入照片（规划中） | 客户手上已有合适的参考图 | `import` |

**三道防呆（必须有）**：

1. **质量闸**：新模板必须满足
   纹理量 ≥4.0、熵 ≥2.5、清晰度 ≥20、对比度 ≥8。
   否则拒绝 —— 防止客户在**被遮挡/失焦**的画面上点"加为模板"，把攻击学成正常。
   确认无误时可 `force=true` 强制添加，但会被审计标记。
2. **去重闸**：与已有模板相似度 ≥0.98 就不重复添加，避免占满 8 个配额。
3. **审计**：每次添加/删除记录
   `时间 / 操作人 / 来源 / 当时系统的判定结论 / 质量指标 / 是否强制`。
   万一日后出现"为什么这个攻击没报"，能查到是不是有人手工加了个模板。

**为什么不做"自动按天气收集"**：系统的基线准入规则是"正常才入库"，
而环境变化恰恰会被判成异常——自动收集与判据自相矛盾。**人工确认反而更可靠**。

**实测**：给参照物补录一套"阴影版"模板后，同一画面的匹配分数从
**0.287 → 0.9995**，且命中模板正确识别为 `lm0t1`。

## 4. 状态落盘

```
algo/data/sparse/
├── cameras.json            机位索引
├── <cameraId>.json         元数据 + 判定历史 + 哈希表 + 每槽样本的标量指标
└── <cameraId>.npz          每槽样本的缩略灰度图（160×90，算中位数背景用）
```

* 每槽最多保留 8 个样本（`SLOT_CAPACITY`），24 槽 ⇒ 最多 192 个缩略图；
* 缩略图 160×90 灰度 = 14.4 KB/张，单机位约 2.7 MB，远小于存原始帧；
* **基线准入规则**：只有 `normal` / `cold_start` / `transient_event` 的样本才并入基线，
  异常样本一律不进 —— 否则一次遮挡会把基线"污染"成被遮挡的样子；
* **标定画面也会入库**：`POST /sparse/landmarks` 默认 `admitFrame=true`，
  标定用的那张画面会同时作为基线样本（用户既然在这张画面上标定，通常就认为它是正常画面）。
  但入库前要过质量闸：熵 ≥ 3.0、清晰度 ≥ 100、亮度不在极端值、且与已有基线偏离 `dHist ≤ 0.15`。
  任何一条不过就跳过，并在返回里给出 `frameAdmitReason`；
* 哈希表保留最近 800 条，用于 D1 跨采样点比对。

## 9. 已知边界

1. **看不到"过程"**：1 小时一次采样，攻击发生在两次抽样之间就无法得知；
   TTD 下界 = 采样相位（均值 30 分钟）+ 判定耗时。
2. **瞬时事件必然漏检**：3 秒遮挡落在 burst 窗口内的概率 < 1%，这是采样率的物理限制，
   不是算法缺陷。要覆盖事件类攻击必须提高采样频率。
3. **冷启动期不下结论**：同一时段槽需要 ≥3 个样本才"就绪"（1 小时采样 ≈ 3 天）。
   冷启动期只给低置信提示。
4. **跨时段降级**：当前时段槽样本不足时会退回"全局基线"，
   此时光照差异会抬高 `dHist`，判定置信度应打折。
5. **强压缩抹掉噪声**：码率极低的视频可能让帧间时间噪声趋近 0，
   导致 Q3 误判；目前靠"首次抽样不定罪 + D1 优先"缓解。
6. **移位判定依赖纹理**：画面的纹理太少（大片天空/白墙）时相位相关不可靠。

## 10. 与实时链路的关系

本仓库**只保留低频巡检**。早期版本还有一条"实时监控"链路（1~10 秒一帧、状态存进程内存、
连续 N 帧去抖告警），它在重构中已移除——两条链路的判定模型和状态管理完全不同，
同时维护会让代码与文档都变重。

如果将来需要实时链路，关键差异是：

| | 实时监控（已移除） | 低频巡检（当前） |
|---|---|---|
| 采样 | 1~10 秒一帧 | 1 小时 ~ 1 天 |
| 状态 | 算法层内存，30 分钟过期 | 按 cameraId 落盘，长期保留 |
| 判定 | 连续 N 帧告警去抖 | 三层信号 + 稳定性分解 |
| 能力 | 事件类攻击、即时告警 | 持续篡改、冻结重放、渐变 |
| 成本 | 高（持续拉流） | 极低（每天 24 次抽样） |
